## 3. Q11 专项：两种清理不是一回事

真实证据：`.superagent-state.json` 曾被提交进仓库，含内部 hostname / 机器名（如 `*.prod.internal`、`*.local`）与内部域名 `code.internal`；`server.ts` 曾硬编码 `IM_WEBHOOK_SECRET` 默认值。**核实更正**：state 里出现的 `sk-2041` 等字串是任务 id `task-2041` 的子串，并非独立密钥值，不应做全局替换。当前工作树已脱敏，但 `8eae911` 起的 git 历史仍保留这些原始 blob。

| 维度 | 只清理当前版本 | 清理 git 历史（需 force push / 轮换密钥） |
| --- | --- | --- |
| 动作范围 | 移出版本控制、加 `.gitignore`、state 脱敏、默认 IM secret 改由 env 注入（S0-3 技术部分） | 重写已含该文件的历史提交，使旧 blob 从远端消失；并轮换可能已泄露的密钥 |
| 是否可逆 | 基本可逆（本地提交可回退） | **不可逆**：历史重写后旧 commit 引用失效 |
| 副作用 | 历史中的 hostname / 模拟密钥串仍可被检出，合规残留 | ① 历史重写影响协作者：所有人需重新 clone / 变基，基于旧历史的本地分支会失配；② 远端分支保护：若 `origin/main` 有保护规则，force push 可能被拒或需临时调整；③ 密钥轮换范围：需覆盖 `IM_WEBHOOK_SECRET` 及历史中出现过的模拟密钥串，含引用它们的配置与 IM 回调验签配置 |
| 授权 | 属 S0-3 技术部分，随 S0 推进 | **必须单独授权**，且不在本材料内执行 |
| 验收口径 | 计划 §5.0：文件不含 hostname / 密钥、默认 IM secret 由 env 注入 | 计划 §5.0 未把「历史清理」列入 S0-3 验收项，需拍板时一并明确 |

> **清理 git 历史不可逆、必须单独授权**。它与第 4 节的普通 `git push` 是两件事，force push 的影响面另计，不与 S0-6 合并授权。

## 7. 本材料的边界

- **不替用户做产品 / 安全决策**：只给选项、代价、拍板人与影响；所有「倾向」均显式标注（建议，仅供参考），Q5 的「必须 B」按计划标为不可协商。

- **不发起外部动作**：无网络请求、无真实模型 CLI 调用、无 push；授权事项仅列出，待用户单独确认。
- **不含日历工期与人力 / 额度预算**：沿用计划 §11「以依赖顺序 + 验收口径驱动」。
- 结论拍板后由对应负责人按第 6 节回写 spec 与计划 §6；本材料自身不作为决策登记处。
