## 5. 已实现的能力（真的能跑，不是占位）

### 5.1 状态机：11 态

原始 8 态 + 本轮补 3 态：`BLOCKED_BY_RESOURCE`（资源阻塞）、`QUARANTINED`（污染隔离）、`WAITING_APPROVAL`（长时等人）。

- 唯一裁决入口 `canTransition()`；`VALID_TRANSITIONS` 穷举，前端 `TASK_STATE_META` 用 `Record` 保证新增态不漏展示。
- 非法迁移**零副作用**（`applyResourceTransition` 先判定后写入）。

### 5.2 三端口（Ports & Adapters）

| 端口 | 本地实现 | 生产目标 | 契约要点 |
| --- | --- | --- | --- |
| `StateStore` | `createFileStateStore` | Postgres | `save()` tmp + `renameSync` 原子；`load()` 损坏抛错不静默回退；`appendCommand` 按 `commandId` 去重、`seq` 实时重算 |
| `IdentityProvider` | `createLocalProvider`（dev header） | OIDC | 4 角色 `viewer/developer/reviewer/admin`，9 个 `Action`，匿名最多 `read` |
| `CommandBus` | `createCommandBus` | Temporal | 幂等（重复命令返回首次结果，HTTP 层 409） |

### 5.3 真实运行时

`advance` 的 `RUNNING → VERIFYING` 分支调 `runRealVerifier()`，**真跑** `npm run lint` + `npm test`，按退出码判定。不伪造 `typecheck` / `cross_review`（未执行就不产出该项）。回退演示态：`SUPERAGENT_DEMO_MODE=1` 或 `SUPERAGENT_REAL_RUNTIME=0`。

### 5.4 M14：真实 git worktree

`git worktree add/remove` 真建真删，落在 `.worktrees/<taskId>`（已 gitignore），分支 `agent/<taskId>`。

- `spawnSync('git', args)` 无 shell；taskId/baseRef 白名单；`canonicalPath()` realpath 归一化；同 taskId 幂等；失败只清空目录不留半成品。
- 端点：`POST/DELETE /api/tasks/:id/worktree`、`GET /api/workspaces`；UI 在检验舱终端页签有「创建/删除工作树」按钮。
- **已知边界**：单仓（Q9 已按单仓实现）；跨仓写集调度属 S5-4，未做。

### 5.5 MCP server

`/api/mcp` 是标准 JSON-RPC 2.0 端点：`initialize`（协议版本协商）/ `tools/list` / `tools/call` / `ping`，支持批量与通知，错误码 `-32700/-32600/-32601/-32602/-32603`。三个工具：

| 工具 | 作用 | 安全约束 |
| --- | --- | --- |
| `recall_memory` | 按四级 ACL 召回已发布记忆 | 实现层过滤 + 出口再兜底过滤，draft 绝不出站 |
| `get_task` | 取单任务状态 | 只读 |
| `list_blocked_tasks` | 列出阻塞节点 | 只读、可带 teamId |

`/api/mcp/recall` 已退为兼容入口（旧 HTTP POST 形态）。

### 5.6 控制台

React 19 + `@xyflow/react` 12 + zustand 5 + Tailwind 4，四个 tab：需求队列 / DAG 画布 / 记忆中心 / 团队协议。DAG 节点可点开检验舱（终端、verifier 检查、门禁、评论）。

## 6. 本轮修掉的 7 个真实缺陷（含根因，避免重复踩）

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | `.env` 完全不生效 | `dotenv` 是依赖但 `server.ts` 从未 import | 首行 `import 'dotenv/config'` |
| 2 | 只读端点要求写权限、`/api/reset` 谁都能调 | `actionFor()` 对未登记路由**默认返回 `task:advance`** | 改显式 `ROUTE_ACTIONS` 表 + 写方法未登记即 fail-closed 403 + 新增 `admin:reset` |
| 3 | 中文记忆召不回（标题里有「对账单 幂等」却 0 条） | Jaccard trigram 在「短查询 vs 长文档」时分母被语料主导，天然偏低 | 改 `computeQueryCoverage`（查询侧覆盖率）+ 标题加权 0.4/正文 0.6；Jaccard 只留给去重 |
| 4 | `reset` 会改坏仓库的 hook | seed 里 TeamAI 资产写的是 **pnpm** 命令（`pnpm typecheck` 本仓库根本不存在），且 `reset` 无条件覆写 `.teamai/` | seed 改 `npm` 命令；`syncTeamAiFileToDisk(overwrite=false)` 不再覆写人工维护文件 |
| 5 | MCP 客户端收到 HTML 而非 JSON-RPC 错误帧 | `express.json()` 解析失败走默认 HTML 错误页 | 错误中间件对 `/api/mcp` 转 `-32700` |
| 6 | 状态机拒绝时客户端只能猜被拒的源态 | `resource-transition` 400 响应缺 `from`/`to` | 400 回带 `from`/`to` |
| 7 | 小屏下检验舱不可达（滚不到） | `DagCanvas` 撑满剩余高度把右栏挤出可视区 | `max-h-[65vh] lg:max-h-none`（仅窄屏生效） |

另有两个隐蔽问题值得记住：

- **macOS `/var` → `/private/var` 是软链**，而 `git worktree list` 输出 realpath。不做归一化会「自己刚建的工作树查不到」，幂等与删除全失效。
- **`.worktrees/` 必须进 `.gitignore` 或 `info/exclude`**，否则主仓 `git status` 被工作树污染。

## 7. 不可破坏的架构约束（红线，改代码前先看）

1. **不伪造执行结果**。verifier 只报真实跑过的项；未执行就不产出该 check。`syncedToGit` 恒 `false`（本地写盘 ≠ 同步 git）。
2. **状态迁移唯一裁决**是 `canTransition()`。任何新路径都不得绕过它自行 set state。
3. **写操作 fail-closed**。RBAC 只放行显式登记的路由；未登记的写方法一律 403，不给默认动作。
4. **draft 资产绝不出站**。召回实现层过滤 + MCP 出口二次兜底。
5. **审计先写后执行**，审计条目不可变、脱敏、`seq` 严格递增。
6. **命令幂等**。`commandId` 去重是硬要求；重复命令返回首次结果而非二次执行。
7. **状态快照原子写**（tmp + rename）。读损坏文件抛错并隔离为 `.corrupt-<ts>`，绝不静默回退到空状态。
8. **状态机非法迁移零副作用**：先判后写。
9. **工作树路径与 ref 白名单**，不允许任意路径/分支注入；git 调用无 shell。
10. **单进程单写者假设**。多 worker 并发写同一日志需文件锁或换生产 adapter——这条已写进 `platform-ports.md` 的「常见错误」。

## 9. 已知环境坑（本机特有，避免重复排查）

1. **没有 `npm run typecheck`**，`lint` 就是 `tsc --noEmit`。teamai 资产里若出现 `pnpm typecheck` 一律是错的。
2. **`sed -i ''`** 在 WorkBuddy 沙箱里会被 `brokered-bin/sed` shim 破坏（报 `No such file or directory`）；用 perl 或把 `/usr/bin` 前置。
3. **后台 `npm run dev` 被 kill 会报 exit 143**（SIGTERM），是主动停止，不是崩溃。重启用 `run_in_background`。
4. 冒烟脚本会改运行态（任务状态、`worktreePath`），**末尾自动 `reset` 复位**；手工 curl 弄脏后手动 `POST /api/reset` 即可。
5. `reset` 不会覆写 `.teamai/` 人工维护文件（已修），但会重建内存态种子数据。
